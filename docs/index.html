Relay

An end-to-end encrypted channel between an app and the server it belongs to, through relays that cannot read it. Pair once with a QR code; after that the phone reaches its server from anywhere, and at home the traffic never leaves the house. Un canal cifrado de extremo a extremo entre una app y el servidor al que pertenece, a través de relays que no pueden leerlo. Se empareja una vez con un código QR; desde entonces el teléfono llega a su servidor desde cualquier sitio, y en casa el tráfico no sale de casa.

WhyPor qué

Your server, reachable. Your data, unreadable on the way.Tu servidor, alcanzable. Tus datos, ilegibles por el camino.

A server that runs in an office or at home usually has no public address, and opening a port or a VPN for every phone is work most people never do. A relay solves the address problem: both ends dial out to it, and it joins them. The hard part is trust. This project makes the relay a pipe that carries only ciphertext, so it does not matter who runs it: us, you, or a stranger.

Un servidor que funciona en una oficina o en casa casi nunca tiene una dirección pública, y abrir un puerto o una VPN para cada teléfono es un trabajo que casi nadie hace. Un relay resuelve el problema de la dirección: los dos extremos se conectan hacia él y él los une. Lo difícil es la confianza. Este proyecto hace del relay un tubo que solo transporta texto cifrado, así que da igual quién lo opere: nosotros, tú o un desconocido.

End to endDe extremo a extremo

Only the phone and its server hold keys. Every connection gets fresh keys, so a key stolen later does not open what was recorded before.

Solo el teléfono y su servidor tienen llaves. Cada conexión usa llaves nuevas, así que una llave robada más tarde no abre lo que se grabó antes.

Many relays, one listVarios relays, una lista

The server keeps an ordered list: a relay on its own network first, a public one after. The phone uses the first that answers and moves back up when it can.

El servidor tiene una lista ordenada: primero un relay en su propia red, después uno público. El teléfono usa el primero que responde y vuelve a subir en cuanto puede.

AuditableAuditable

A published framework (Noise), a protocol document precise enough to reimplement, and test vectors that every library passes, in three languages.

Un marco publicado (Noise), un documento de protocolo preciso como para reimplementarlo y vectores de prueba que pasan todas las bibliotecas, en tres lenguajes.

How it worksCómo funciona

Two ends, any number of relays in between.Dos extremos, los relays que hagan falta en medio.

The host is the end that is always on: the server. The guest is the end that comes and goes: the phone. Both open a WebSocket to a relay, the relay joins the two sockets of a channel, and passes frames from one to the other without opening them. The host keeps a channel on every relay of its list; the guest uses one at a time.

El host es el extremo que siempre está encendido: el servidor. El guest es el extremo que va y viene: el teléfono. Los dos abren un WebSocket hacia un relay; el relay une los dos sockets de un canal y pasa los frames de uno a otro sin abrirlos. El host mantiene un canal en cada relay de su lista; el guest usa uno a la vez.

Both ends dial out. Relays see ciphertext and timing, never content or keys. The dashed line is the fallback road. Los dos extremos se conectan hacia fuera. Los relays ven texto cifrado y tiempos, nunca contenido ni llaves. La línea discontinua es el camino de reserva.

Run your ownTu propio relay

One static binary.Un solo binario estático.

The relay is a small Go program with no runtime dependencies. Since confidentiality never depends on the relay, running your own is about availability and metadata: on your own network, nobody else sees when your devices talk.

El relay es un programa pequeño en Go, sin dependencias en tiempo de ejecución. Como la confidencialidad nunca depende del relay, tener el tuyo es cuestión de disponibilidad y de metadatos: en tu propia red, nadie más ve cuándo hablan tus dispositivos.

Build and startCompilar y arrancar

# Go 1.27 or later
git clone https://github.com/syalia-srl/relay
cd relay/server
CGO_ENABLED=0 go build -o relay ./cmd/relay

RELAY_ADDR=127.0.0.1:8010 \
RELAY_STATE_PATH=/var/lib/relay/channels.json \
RELAY_KEYS_PATH=/etc/relay/keys.json \
./relay

Or as a container: docker build -t relay server/, with /data as a volume. It belongs behind a TLS proxy, because guests accept plain ws:// only to private addresses.O como contenedor: docker build -t relay server/, con /data como volumen. Va detrás de un proxy con TLS, porque los guests solo aceptan ws:// en claro hacia direcciones privadas.

Who may create channelsQuién puede crear canales

{
  "relay_id": "relay.example",
  "keys": [
    { "id": "office", "sha256": "<hex of your key>",
      "channels": 200, "creates_per_minute": 20,
      "bytes_per_day": 2000000000 },
    { "id": "home", "sha256": "<hex of another key>",
      "unlimited": true }
  ],
  "issuers": {}
}

Each key has its own quota, so one product cannot starve another. A quota of 0 allows nothing; only "unlimited": true lifts the limits, for a relay you run for yourself. The file holds digests, never keys. A vendor can also issue signed relay tokens; list its public key under issuers.Cada llave tiene su propia cuota, así que un producto no puede dejar sin servicio a otro. Una cuota de 0 no permite nada; solo "unlimited": true quita los límites, para un relay que operas para ti. El archivo guarda digests, nunca llaves. Un proveedor también puede emitir tokens de relay firmados; pon su llave pública en issuers.

Build on itConstruye encima

The same protocol in three languages.El mismo protocolo en tres lenguajes.

Each library implements both ends: pairing, the Noise handshakes, framing, control messages and relay failover. Each carries its own small Noise for the two patterns it needs, with no Noise dependency, and every host is tested against every guest through the relay. A guest can keep its private key in native code: the libraries only ask for Diffie-Hellman results.

Cada biblioteca implementa los dos extremos: emparejamiento, handshakes Noise, frames, mensajes de control y cambio de relay. Cada una lleva su propio Noise pequeño para los dos patrones que necesita, sin depender de ningún paquete de Noise, y cada host se prueba contra cada guest a través del relay. Un guest puede guardar su llave privada en código nativo: las bibliotecas solo piden resultados de Diffie-Hellman.
